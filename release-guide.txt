 Step 1 — Create a release keystore

  Set JAVA_HOME to a JDK 21 installation, then run this in PowerShell
  (pick your own values for the -dname fields):

   $keytool = Join-Path $env:JAVA_HOME "bin\keytool.exe"

   & $keytool -genkeypair `
     -keystore "$env:USERPROFILE\.android\whispertranscriber-release.jks" `
     -alias whispertranscriber `
     -keyalg RSA -keysize 2048 -validity 10000 `
     -dname "CN=Your Name, O=Your Org, C=IT"

  It will prompt for a store password and a key password — pick strong ones and save them in a password manager.

  ----------------------------------------------------------------------------------------------------------------------

  Step 2 — Derive the 4 secret values

   # RELEASE_KEYSTORE_BASE64
   [Convert]::ToBase64String(
     [IO.File]::ReadAllBytes("$env:USERPROFILE\.android\whispertranscriber-release.jks")
   ) | Set-Clipboard
   # Now paste it as the RELEASE_KEYSTORE_BASE64 secret value

   # The other three come from what you chose above:
   # KEYSTORE_PASSWORD  → the store password you entered
   # KEY_ALIAS          → whispertranscriber   (or whatever alias you used)
   # KEY_PASSWORD       → the key password you entered

  ----------------------------------------------------------------------------------------------------------------------

  Step 3 — Add secrets to GitHub

  Go to: Your repo → Settings → Secrets and variables → Actions → New repository secret

  Add all four:

  ┌───────────────────────────┬──────────────────────────────────────────────────────────────┐
  │ Secret                    │ Value                                                        │
  ├───────────────────────────┼──────────────────────────────────────────────────────────────┤
  │ RELEASE_KEYSTORE_BASE64   │ output of the [Convert]::ToBase64String(...) command above   │
  ├───────────────────────────┼──────────────────────────────────────────────────────────────┤
  │ KEYSTORE_PASSWORD         │ store password from Step 1                                   │
  ├───────────────────────────┼──────────────────────────────────────────────────────────────┤
  │ KEY_ALIAS                 │ whispertranscriber                                           │
  ├───────────────────────────┼──────────────────────────────────────────────────────────────┤
  │ KEY_PASSWORD              │ key password from Step 1                                     │
  └───────────────────────────┴──────────────────────────────────────────────────────────────┘

  ----------------------------------------------------------------------------------------------------------------------

  Step 4 — Tag and release

   Use a tag beginning with v followed by a valid SemVer version, for example
   v1.0.0 or v1.1.0-rc.1. The workflow derives versionName from the tag without v
   and versionCode from the number of commits reachable from the tagged commit.

   The tag commit must already be contained in main. The release workflow reuses
   successful CI checks from a push to main for that exact commit. It waits up to
   35 minutes for a running CI workflow and blocks publication if CI fails or is
   cancelled. If no run is found after one minute, it runs the full CI suite;
   otherwise it runs only the jobs or device suites whose required checks were
   missing or skipped. A green aggregate gate alone is not sufficient evidence.

   The release still builds a fresh signed APK, requires all four signing secrets,
   and rejects unsigned or Android-debug-signed APKs.

   git tag v1.0.0
   git push origin v1.0.0

   ⚠️ Back up whispertranscriber-release.jks somewhere safe (cloud storage, password manager). If you lose it, you can
   never update the app under the same signature.
